# PlexonTravel 3.0.1

PlexonTravel 3.0.1 is the stability follow-up to the 3.0 full travel-suite release. It was produced after a full source audit prompted by a production report where `/warps` showed that PlexonTravel 3.0.0 had already disabled during startup.

## Startup and persistence hardening

The `/warps` stack trace was a secondary symptom: Bukkit rejects all plugin commands after a plugin has disabled. Version 3.0.1 makes every startup phase explicit and guarded, including Core discovery/registration, SQLite loading, runtime construction, command/listener/service registration, and ticker startup. An unexpected startup failure now reports the exact phase and keeps the Core module state as `FAILED` for diagnosis.

The SQLite schema remains compatible with 1.x, 2.x and 3.0.0. However, 3.0.0 treated any malformed persisted row as fatal to the whole plugin. 3.0.1 isolates malformed destination, warp, or back rows, logs the affected key, and continues loading valid data.

## Performance and chunk safety

Normal spawn/hub/warp/API safety resolution no longer creates new chunks by default. The nearby safety search also refuses to synchronously inspect unloaded adjacent chunks, preventing accidental server-thread chunk loads under larger player counts.

RTP remains bounded and asynchronous. In addition, an in-flight RTP lookup is now cancelled when its player quits, dies, changes worlds, or the plugin shuts down, and stale async callbacks cannot teleport a player back into the world where an old search started.

## Player and integration fixes

- Individual spawn, hub, back, warp, and RTP permissions are now enforced inside the service layer as well as command declarations, closing `/travel`, `/ptravel`, and GUI permission bypasses.
- Accepted TPA requests now surface terminal teleport failure instead of reporting acceptance and then silently doing nothing.
- Hidden players are excluded from TPA request resolution where visibility applies.
- Malformed MiniMessage customization is rendered literally and logged once instead of throwing through player commands or menus.
- Inventory GUI titles use Adventure components rather than the deprecated string-title path.
- PlaceholderAPI spawn/hub status is world-aware for online players, and warp count uses cached O(1) state instead of materializing the full warp list.
- Older partial `config.yml` files may omit newly introduced keys and inherit embedded defaults; explicit invalid values are still rejected.
- Expired cooldown maps are pruned periodically, persistence shutdown is bounded, and late persistence writes are safely rejected.
- Warp display/category metadata is bounded before entering the runtime cache.

## Compatibility

- Paper: `26.2.build.121-stable`
- Java: `25`
- PlexonCore: `2.0.5` / Core API `2.0`
- Existing PlexonTravel SQLite data is retained.
- Existing global spawn/hub entries remain compatibility fallbacks for per-world destinations.

## Deployment note

GitHub build/release verification proves the exact source, tests, packaged JAR and published checksum. It does not replace live PlexonCraft startup certification. After installing 3.0.1, verify the earlier startup section of `latest.log`; if startup still fails, 3.0.1 will now name the exact failing phase instead of leaving `/warps` as the only visible symptom.

Rollback: `v3.0.0`.
