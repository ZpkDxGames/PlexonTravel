# PlexonTravel 3.0.0

PlexonTravel 3.0.0 turns the focused 2.x travel module into PlexonCraft's full Core-native travel suite. It is designed to replace overlapping Essentials warp commands, WorldSpawn-style spawn/hub routing and a separate RTP command provider with one per-world runtime.

## New travel surface

- Per-world `/spawn` and `/hub`, configured with `/setspawn` and `/sethub` in the current world.
- Global fallback setters remain available as `/setspawn global` and `/sethub global` for migration compatibility.
- `/warp` and `/warps` remain cached PlexonTravel destinations with a refreshed browser.
- First-class `/tpa`, `/tpahere`, `/tpaccept`, `/tpdeny` and `/tpcancel`.
- First-class `/rtp` with a dedicated player GUI.
- New `/travel` help/navigation GUI.

## Unified player experience

Spawn, hub, warps, back, TPA and RTP now share the same safe travel engine: configurable five-second warmup, bossbar countdown, MiniMessage messages, warmup particles, movement/damage cancellation, asynchronous teleport and completion particles/sound.

## RTP defaults

RTP is enabled for `Survival_World` by default. Candidates are selected between 2,000 and 10,000 blocks from the central point, which defaults to the world's vanilla spawn. Sampling is uniform by area inside the annulus rather than clustering players near the minimum radius.

Searches are bounded, respect the world border, load eligible chunks asynchronously and do not generate new terrain by default. This keeps RTP suitable for a pregenerated Survival world and prevents accidental world-generation spikes under load.

## Performance and architecture

The previous large runtime class has been split into dedicated destination, storage, teleport, TPA, RTP, menu and command services. Destinations and warps stay cached in memory; SQLite writes remain serialized off-thread; warmups share one five-tick ticker; RTP uses bounded async chunk acquisition; and PlaceholderAPI remains cached/API-only.

## PlexonCore integration

This release targets PlexonCore 2.0.5 / Core API 2.0 and advertises per-world destinations, TPA, RTP and MiniMessage UI capabilities. The public API adds world-aware `spawn(UUID)` and `hub(UUID)` methods while preserving the existing global methods for binary/source compatibility.

## Upgrade and cutover

PlexonTravel 3.0.0 defaults standard command takeover to enabled. `plugin.yml` also declares load-before relationships for Essentials, WorldSpawn and BetterRTP to make a staged transition less fragile. A clean PlexonCraft deployment should still disable/remove overlapping legacy command modules after verification instead of permanently depending on registration order.

Existing PlexonTravel 2.x SQLite destination, warp and back data remains compatible. Existing global spawn/hub entries become compatibility fallbacks until per-world destinations are configured.

Essentials warp import remains explicit and source-read-only. Run `/traveladmin migrate scan` and `/traveladmin backup` before temporarily enabling `migration.allow-execute`.

## Runtime certification

GitHub source/build/release verification does not substitute for live PlexonCraft runtime certification. The published provenance records runtime certification as `NOT_EXECUTED`; validate command ownership, each per-world destination, TPA acceptance/cancellation and Survival RTP on the production host before removing rollback assets.
