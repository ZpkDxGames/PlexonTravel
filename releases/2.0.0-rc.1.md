# PlexonTravel 2.0.0-rc.1

Phase 2 release candidate. Runtime certification is intentionally pending.

## Phase 2
- Authoritative per-player attempt identity now starts before safe destination resolution and remains owned through async teleport terminal state.
- Duplicate warmup/in-flight requests are rejected rather than replacing active travel.
- Fee ownership has a single compensation path and executing attempts cannot be cancelled out from under their terminal callback.
- Warp deletion is actor/action/warp/revision-bound, expiring and one-shot.
- `renamewarp` updates display metadata while preserving stable warp IDs.
- Warp browser exposes locked state and default fee context.
- Candidate configuration is validated before reload activation; malformed reloads retain the prior known-good runtime.
- PlaceholderAPI expansion exposes cached-only travel state.
- CI certifies Java 25/class-major 69, provided-dependency boundaries, test totals, provenance and checksum assets.

## Compatibility
The focused `/spawn`, `/hub`, `/back`, `/warp`, `/warps`, `/ptravel` and travel administration product remains intact. Existing SQLite destination/warp/back schema is preserved; no destructive database migration is required from v1.0.1.

## Certification boundary
The RC tag is created only after exact-head source CI and draft-PR CI both succeed on the same commit. GitHub source/tag CI is not PlexonCraft runtime certification. Production migration, command ownership, TheosisEconomy/Vault behavior, restart/soak, PlaceholderAPI, interoperability and Spark/MSPT gates remain pending.
