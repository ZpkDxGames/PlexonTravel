# PlexonTravel 3.1.0

PlexonTravel 3.1.0 expands the existing Core-native travel runtime with per-world RTP administration and first-class void rescue while preserving the accepted 3.0.2 spawn, hub, warp, back, TPA, RTP, persistence, startup, and migration behavior.

## RTP remains first-class

Player commands are unchanged:

```text
/rtp
/rtp now
```

The 3.0.x global RTP configuration remains valid. When a world has no explicit 3.1 profile, PlexonTravel resolves the existing `rtp.enabled`, `rtp.allowed-worlds`, center, radius, attempt, and chunk-generation settings into an equivalent inherited ANNULUS profile. Existing operators do not need to rebuild their configuration during upgrade.

## Per-world RTP profiles

3.1 adds `world-settings.yml`, keyed by durable world UUID with a last-known human-readable world name. Runtime policies are parsed and validated into immutable cached models; RTP searches do not parse YAML or perform filesystem/database work on their hot path.

Supported boundary modes:

- `ANNULUS` — preserves the existing uniform-area radial behavior with world-spawn or configured X/Z center.
- `RECTANGLE` — uniform sampling inside explicit min/max X/Z bounds.
- `WORLD_BORDER` — samples the active Minecraft world border with configurable inward padding.

Every mode is intersected with the live Minecraft world border. Empty/impossible effective regions fail closed before a search begins.

Administrative surface:

```text
/traveladmin rtp status [world]
/traveladmin rtp enable <world>
/traveladmin rtp disable <world>
/traveladmin rtp mode <world> <annulus|rectangle|world-border>
/traveladmin rtp center <world> <spawn|here|x z>
/traveladmin rtp radius <world> <min> <max>
/traveladmin rtp bounds <world> <minX> <maxX> <minZ> <maxZ>
/traveladmin rtp pos1 [world]
/traveladmin rtp pos2 [world]
/traveladmin rtp padding <world> <blocks>
/traveladmin rtp attempts <world> <count>
/traveladmin rtp generate <world> <true|false>
/traveladmin rtp reset <world>
/traveladmin rtp test [world] [samples]
```

`rtp test` is bounded and non-teleporting. It reports the effective boundary mode, sampled coordinate range, accepted/rejected candidates, and candidates rejected because chunks are not generated.

## Void rescue

Void rescue is independently configurable per world and defaults to disabled until explicitly enabled. Each world may set its own trigger Y, rescue destination, and creative-mode behavior.

Destination modes:

- `PLEXON_SPAWN`
- `PLEXON_HUB`
- `WORLD_SPAWN`
- `FIXED` via `/traveladmin void destination <world> here`

Administrative surface:

```text
/traveladmin void status [world]
/traveladmin void enable <world>
/traveladmin void disable <world>
/traveladmin void threshold <world> <y>
/traveladmin void destination <world> <spawn|hub|worldspawn|here>
/traveladmin void creative <world> <true|false>
/traveladmin void reset <world>
/traveladmin void test [world]
/traveladmin void simulate <world> <y>
```

Automatic rescue has no warmup, economy fee, or ordinary travel cooldown. It uses a dedicated internal system-teleport path, resets fall distance after success, deduplicates in-flight rescue operations, applies a bounded failure backoff, excludes spectators by default, and leaves creative rescue disabled unless configured.

`plexontravel.voidrescue.bypass` defaults to operators and suppresses automatic rescue for builders/debugging.

## `/back` safety

Void rescue is marked as an internal teleport. Its unsafe void source is not captured as an external teleport and does not replace an existing useful `/back` entry. A death racing a rescue also avoids committing the unsafe void coordinate as back history while rescue is in flight.

## Administration and validation

New permissions:

```text
plexontravel.admin.rtp
plexontravel.admin.void
plexontravel.voidrescue.bypass
```

World-setting mutations are candidate-first: mutate in memory, validate completely, write through a temporary file with atomic/replace semantics where supported, and activate only after persistence succeeds. Invalid radius ordering, rectangles, padding, attempt counts, trigger values, or destination definitions fail closed.

`/traveladmin reload` validates both `config.yml` and `world-settings.yml` before activation. Existing 3.0.x partial configs continue to inherit embedded defaults.

## Performance model

- cached immutable world policies keyed by UUID;
- no YAML, filesystem, SQL, or database access in movement-event evaluation;
- void rescue returns immediately for movement that does not change Y;
- one in-flight rescue per player;
- RTP keeps bounded cancellable asynchronous chunk acquisition;
- terrain generation remains disabled by default;
- no blocking `.join()`/waits on the server thread;
- world-border intersection is resolved before RTP sampling begins.

## Diagnostics

`/traveladmin diagnostics` now reports explicit/inherited RTP profile counts and void-rescue attempts, completions, failures, enabled-world count, and active rescue operations in addition to the existing travel/TPA/RTP counters.

- Paper: `26.2.build.121-stable`

- PlexonCore: `2.0.5` / API 2.0
- SQLite schema/data: unchanged
- Existing 2.x/3.x upgrade compatibility: preserved
- Existing `commands.takeover-enabled`: preserved
- Existing player travel commands and permissions: preserved
- `world-settings.yml` is additive and can be ignored by 3.0.2 during rollback

Live PlexonCraft movement behavior remains a separate production certification boundary and must be reported as pending unless tested on the real host.
