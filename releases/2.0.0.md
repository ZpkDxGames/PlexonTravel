# PlexonTravel 2.0.0

Stable GitHub repository closure of the accepted PlexonTravel Phase 2 / Phase 3 runtime line.

## Reliability and correctness

- Authoritative per-player attempt identity begins before safe-destination resolution and remains owned through warmup, final validation, charging, asynchronous teleport and terminal completion.
- Duplicate warmup or in-flight travel requests are rejected rather than replacing active travel.
- Executing attempts cannot be cancelled out from under their async terminal callback.
- Fee ownership has one compensation path: failed charged travel refunds once, successful travel commits history/cooldown once, and warmup cancellation is not charged.
- Safe teleport validation remains bounded and revalidates the destination before charge/teleport.
- `/renamewarp` updates display metadata while retaining stable persistence identity.
- `/delwarp` requires actor/action/resource/revision-bound, expiring, one-shot confirmation.
- Candidate configuration is validated before activation; malformed reloads retain the prior known-good runtime.
- PlaceholderAPI exposes cached/API travel state only.

## Compatibility

- Paper 26.2 / Java 25.
- Exact external PlexonCore 2.0.4 integration.
- Existing SQLite destination, warp, back and migration metadata remain compatible with `v1.0.1`.
- SQLite JDBC remains bundled; Paper/Bukkit/Adventure/Core/PlaceholderAPI/Vault remain external.
- TPA is not added. BetterRTP and AdvancedPortals remain outside PlexonTravel.

## Production cutover boundary

Stable GitHub publication does **not** enable production command takeover or migration execution. Defaults remain `migration.claim-standard-commands: false` and `migration.allow-execute: false` until an operator completes the documented live ownership/migration checks.

Live PlexonCraft runtime certification may remain `NOT_EXECUTED` in release provenance and is a deployment follow-up rather than a source/release blocker.

## Release verification

The exact final `main` source is rebuilt and tested before release. Publication includes the runtime JAR, `SHA256SUMS.txt`, `TEST_SUMMARY.txt` and `PROVENANCE.txt`; the workflow downloads those published assets and verifies the checksum and exact source commit before completing.

Rollback baseline: `v1.0.1` / `772188d55c694deea0bc5ae0bdce0898513499e5`.
